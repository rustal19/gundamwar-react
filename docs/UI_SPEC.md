## 1. 共通ヘッダー

### PC(幅 >1100px)
```
[Gundam War Portal]  検索  公開デッキ  大会  デッキ構築        [ニックネーム ▾]
```
- 左: ブランド(テキストロゴ)。クリックで `/`。下に 11px の副題「ガンダムウォー非公式ポータル」
- ナビ4項目(順序固定): 検索(/search) / 公開デッキ(/decks) / 大会(/tournaments) / デッキ構築(/deck)
  - アクティブ表示: 文字 `--gw-primary` + 下線 `--gw-accent` 2px(DESIGN_SPEC §3)
- 右(未ログイン): **「ログイン」ボタン1つ**(secondary様式)。押すと Google サインイン
  (mock時はロール選択付きモックログイン)。「未ログイン」ラベルは廃止
- 右(ログイン済み): **ニックネーム+▾ のメニューボタン**。クリックでドロップダウン:
  1. プロフィール(/profile)
  2. 大会を作成(/tournaments/new)— organizer/admin のみ表示
  3. 権限管理(/admin/users)— admin のみ表示
  4. ─区切り─ ログアウト
  - 外側クリック/Escで閉じる。`aria-expanded`・`role="menu"` を付ける

### モバイル(compact)
- 上段: ブランド+ハンバーガー(現状踏襲)
- 開いたメニュー: ナビ4項目 → 区切り → ログイン済みなら上記メニュー項目と同内容/
  未ログインなら「ログイン」ボタン。ページ遷移で自動クローズ(実装済み)
- 全リンクは `buildPathWithForcedMobileLayout` でクエリ引き継ぎ(既存ルール)

## 2. 共通フッター(実装済み・変更点のみ)

- 左に「Gundam War Portal」表記を追加。リンク(利用規約/プライバシーポリシー)と
  非公式表記は現状どおり

## 3. ページ別定義

### 3.1 トップ `/`(カード型・サイトの顔)
上から:
1. **ヒーロー**: サイト名(h1)+副題+紹介文1行+**簡易検索ボックス**
   - placeholder「カード名で検索」。Enter/検索ボタンで `/search?<カード名パラメータ>=入力値` へ遷移
     (パラメータ名は SearchForm の name 条件と同一キーを使うこと。実装時に確認)
   - 現状ヒーローの eyebrow と h1 が同文言で重複している問題はこの構成で解消
2. **開催予定・進行中の大会**(最大5件、開始日時昇順)
   - 行: タイトル(リンク)/説明1行/ステータスバッジ/開始日時/参加数(定員)。「もっと見る」→ /tournaments
3. **新着公開デッキ**(最大5件、新着順)
   - 行: タイトル(リンク)/説明1行/投稿者ニックネーム/枚数/公開日
4. **導線カード2枚**: カード検索 / デッキ構築
- ログイン不要。各セクションのエラー・空は行内メッセージ(実装済みパターン)

### 3.2 検索 `/search`(フォーム=中間、結果=高密度)
- SearchForm(compact時アコーディオン)+結果リスト
- 条件なしアクセス時「検索条件を指定してください。」(実装済み)
- 結果ツールバー: 件数・ページャ・**表示切替[詳細|画像のみ]を新設**・「デッキ」ボタン
  - 画像のみ: カード画像のタイルグリッド。クリックで画像拡大(既存 CardImagePreviewDialog)
  - 切替状態はページ内state(URLには持たせない)
- 「Loading...」→「読み込み中...」に統一(DESIGN_HANDOFF 課題3)

### 3.3 公開デッキ一覧 `/decks`(カード型)
- 見出し「公開デッキ」+件数/新着順表記
- 検索ボックス(デッキ名・説明・ユーザー名)+ページャ
- デッキカード: タイトル(リンク)/説明/投稿者/枚数/公開日。カード全面クリック可
- 右上「デッキ作成」→ /deck

### 3.4 公開デッキ詳細 `/decks/:id`(カード型)
- ヘッダ: タイトル/投稿者/公開日+**枚数サマリを追加**(例「メイン50・サイド10」)
- アクション: このデッキをコピー(primary)/ 非公開にする(admin のみ・danger)/ 一覧へ
- 本文: 説明文 → メインデッキ(種別グルーピング)→ サイドボード

### 3.5 デッキ構築 `/deck`
- 現状レイアウト踏襲(PC=2ペイン、モバイル=デッキ/検索タブ)。トークン化と部品統一のみ
- 公開トグルの導線改善は将来課題(DESIGN_HANDOFF 課題7)

### 3.6 大会一覧 `/tournaments`(カード型)
- statusフィルタ(すべて/受付中/進行中/完了/中止)+ページャ
- 大会カード: タイトル(リンク)/バッジ/フォーマット(スイス・シングルエリミ)/開始日時/参加数(定員)
- organizer/admin には「大会を作成」ボタン(primary)を見出し右に表示

### 3.7 大会詳細 `/tournaments/:id`
- ヘッダ: タイトル+バッジ+主催者+開始日時+定員。organizer本人には「管理画面へ」ボタン
- **エントリー枠**(ログイン時・受付中のみ): エントリー/取消ボタン、デッキリスト提出
  (保存デッキから選択 or 現在のデッキ)、レギュレーション違反は一覧表示して提出ブロック
  (実装済み)。進行中は自主ドロップボタン
- タブ4つ(実装済み構成を維持):
  - 概要: 説明・レギュレーション内容(枚数・禁止制限・使用可能セット)
  - 参加者: ニックネームと状態のみ。デッキリストは completed 後に閲覧可
  - ペアリング: ラウンド別テーブル(卓番号/対戦者/結果)— 高密度
  - 順位表: 順位/プレイヤー/勝-敗-分/勝点/OMW% — 高密度、1位行ハイライト

### 3.8 大会管理 `/tournaments/new`・`/tournaments/:id/manage`
- organizer/admin 以外は権限メッセージのみ(実装済み)
- セクション順(現状維持): 大会情報フォーム → ステータス操作 → 参加者 → ラウンド管理 → 順位表
- **追加**: 上部に「次にやること」ガイド行(status連動。例: 受付中=「開始したら『進行開始』→ラウンド生成」)
- 大会情報フォームに**フォーマットプリセット選択**を追加(src/data/formats.js。リスト受領後)

### 3.9 プロフィール `/profile`
- ニックネームの表示・変更(実装済み)。将来: 自分の公開デッキ・参加大会(SITE_DESIGN #9)

### 3.10 権限管理 `/admin/users`
- ユーザー検索+一覧(名前/メール/ロール変更/ニックネームリセット)。高密度・現状構成維持

### 3.11 規約 `/terms`・`/privacy`
- `.legal-page`: 最大幅 720px・行間 1.8 の読み物スタイル(DESIGN_SPEC §5)
